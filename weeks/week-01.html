Week 1 · npm and Vite

The calculator moves from unpkg to npm

Time 6–8 h Start point calculator in git, Scale from unpkg Plan all weeks Method how to work Cheat sheet package.json, npm, Yarn

Goal of the week: your calculator gets Scale from npm, not from unpkg. It starts with npm run dev and builds with Vite. You can explain each line of your package.json.

Why this matters: Scale is a package on npm, and the Scale repo is a project of many packages. Each contribution starts with a package.json, an install, and a script. Your calculator is a small and safe place to learn this before the big repo.

0 · Warm-up (15 min, no notes)

Open your LEARNING-LOG.md (see how to work). Answer from memory, then check in the sources you read before.

  1. What problem does a package manager solve? Give one example from C++ or C# (NuGet).
  2. What do you get when you install Node.js? (Hint: two programs.)
  3. Where can JavaScript run? Name two places.

A · Study (approx. 3 h)

Read in this order. After each source: close the tab, write 3–5 sentences in your log in your own words, then check.

  1. Node.js Learn: Introduction to Node.js · 30 min
    Look for: what Node.js is, and how it is different from JavaScript in the browser. For us, Node.js is mostly the runtime for our tools (npm, Vite, Stencil).
  2. Node.js Learn: An introduction to the npm package manager · 30 min
    Look for: npm install, npm install <pkg>, versions, and the scripts block.
  3. npm docs: dependencies and devDependencies · 10 min
    Look for: which packages your page needs, and which only your tools need.
  4. javascript.info: Modules, introduction · 45 min
    Look for: import/export, <script type="module">, and why the browser needs a path or URL for each import.
  5. MDN: Package management basics · 45 min
    Look for: why we use packages and tools in front-end projects. Read for the ideas; you do not have to do every step on the page.
  6. Video: Fireship — Vite in 100 Seconds (2 min), then Vite: Why Vite · 20 min
    Look for: what a dev server does and what a build does. Do not worry about details like "esbuild" or "Rollup".

B · Build (approx. 3 h)

Do Lesson 0001 — The calculator: from unpkg to npm + Vite. It has all the steps. Work on a branch, and finish with a pull request in your own repo.

C · Check (approx. 1 h)

  1. Do the quiz at the end of Lesson 0001.
  2. Write the answers in your log, from memory:
    • What happens if you delete node_modules/? How do you get it back?
    • Why does the browser not understand import … from '@telekom/scale-components/loader' alone?
    • What is the difference between npm run dev and npm run build?
  3. Check the "Done when" list below.

Done when

  • The calculator runs with npm run dev
  • No unpkg URL is left in the project
  • package-lock.json is in git; node_modules/ and dist/ are not
  • The work is merged with a pull request from a branch
  • You can explain each line of your package.json without notes
  • Your learning log has your predictions, your notes, and your open questions

Bring to the sync

  • The link to your pull request.
  • Your calculator, running with npm run dev.
  • Your learning log, with at least 3 open questions.
  • What you found about latest and next (Lesson 0001, step 4).

If you have time left (optional)

  • Run npm view @telekom/scale-components versions. How many beta versions are there?
  • Open the Scale root package.json. Mark each line you do not understand. This is input for week 2.
  • Try the npm semver calculator with the package vite and the range from your package.json.

Checkpoint for the week 1 sync (agenda: how to run the sync)

Recall (no notes):

  • "npm is like NuGet. What is the same? What is the NuGet equivalent of package.json?" (A .csproj with PackageReference; the lock file is like packages.lock.json.)
  • "Where does Node.js run, and where does your calculator code run?" (Node: on your machine, runs the tools. Calculator: in the browser. A common confusion.)

Show: open the PR. Look at the commits: small steps? .gitignore correct? No node_modules in the diff?

Explain: pick one line of package.json, e.g. "vite": "^8.x.x". Ask what ^ allows (prepares week 2). Then ask: "In DevTools → Network, where do the Scale files come from now?"

latest vs. next: the README says @next, but next points to an older version. Decide with the student if this becomes a small docs PR in week 3.

Red flags: cannot say why Vite is needed; copied the steps without predictions in the log; confuses Node.js with the browser. If so, repeat ideas 1–3 of Lesson 0001 at the start of week 2.

After the sync: tell the teacher agent what the student explained well and what was hard. It writes the week 2 handout from that.
