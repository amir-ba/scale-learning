A: Study (2 h 45 min)

Read in order. Try the small examples. Use the rubber duck approach: explain each idea out loud. Write only the things you do not understand on your question list.

  1. Promises, then async/await (javascript.info): 50 min.
    Look for: pending, fulfilled, rejected; what await waits for; how try/catch handles a rejection. An async function returns a promise. It does not turn JavaScript into a blocking C++ program.
  2. Node.js: promise-based file API: 25 min.
    Look for: readFile from node:fs/promises. Find the encoding argument and error handling. Read that API entry, not the whole page.
  3. Node.js: determining the module system: 25 min.
    Look for: .mjs, .cjs, "type": "module", import and require. Our report uses .mjs; you do not need to change the calculator's module settings.
  4. npm: semantic versioning and the semver calculator: 35 min.
    Try: ^1.2.3, ~1.2.3 and ^0.2.3. Then try Scale's actual prerelease range. Prereleases have extra matching rules; do not guess from stable versions. A dist-tag such as next is a movable name, not a version range.
  5. npm: scripts: 20 min.
    Look for: the script working directory, local tool lookup and pre/post hooks. Predict the order for prereport, report, postreport.
  6. MDN: Clipboard.writeText(): 10 min.
    Look for: the returned promise, secure contexts and permission failures. A call that starts is not proof that the copy succeeded.

2. Build the dependency report (90 min)

  1. Create scripts/dependency-report.mjs. Read the calculator's package.json with readFile and parse the JSON with JSON.parse.
  2. Read both dependencies and devDependencies. Either field can be absent. Use Object.entries to get each name and range.
  3. For each direct dependency, read its installed package.json from node_modules/. A scoped name such as @telekom/scale-components has two path segments. The version here is the installed version, not the range in your manifest.
  4. Show a table with name, group, requested range and installed version. Do not list all transitive packages.
  5. If a direct dependency is missing, show (missing) and set a nonzero exit code. Do not invent a version from the lock file. Invalid JSON and other read errors must also fail.
  6. Add "report": "node scripts/dependency-report.mjs" to the existing scripts object. Keep the Vite scripts. Run npm run report and compare it with npm ls --depth=0.
One working version: open after your first attempt 
import { readFile } from 'node:fs/promises';

const manifest = JSON.parse(await readFile(
  new URL('../package.json', import.meta.url), 'utf8'
));
const rows = [];

for (const group of ['dependencies', 'devDependencies']) {
  for (const [name, requested] of Object.entries(manifest[group] ?? {})) {
    let installed = '(missing)';
    try {
      const file = new URL(`../node_modules/${name}/package.json`, import.meta.url);
      const dependency = JSON.parse(await readFile(file, 'utf8'));
      installed = dependency.version;
    } catch (error) {
      if (error.code !== 'ENOENT') throw error;
      process.exitCode = 1;
    }
    rows.push({ name, group, requested, installed });
  }
}

console.table(rows);

import.meta.url is the URL of this script. Each new URL resolves a path from that script, not from the terminal's current folder. node:fs/promises is built into Node.js; do not install a package for it.

This report targets your small npm calculator project. It does not resolve every nested dependency or model Yarn workspace hoisting.

3. Predict, break and repair (30 min)

  1. Temporarily add a dependency entry named learning-missing-package with version 1.0.0. Do not install it. Predict the report output and run it. It must show a missing package and fail. Remove only that temporary entry.
  2. Add temporary prereport and postreport scripts that each run node -e "console.log('before')" or node -e "console.log('after')". Escape the inner double quotes in JSON. Predict the order, run the report, then remove the two hooks.
  3. Explain why changing a version range does not itself replace an installed package. Compare the range, installed version and lock file.

4. Handle the existing clipboard promise (45 min)

Find the calculator's current navigator.clipboard.writeText(...) call. Change that handler; do not add a second copy handler.

  1. Add a small status element near the copy control, for example <p role="status" id="copy-status"></p>.
  2. Make the existing handler async. Inside try, await the write. Show Copied. only after it fulfils.
  3. In catch, show a useful message, for example Copy failed. Select the result and copy it manually.. Do not report success from a finally block.
  4. Run the calculator on Vite's localhost URL. Copy a result and paste it into a scratch editor. Clear any old clipboard text first so it cannot hide a failure.
  5. If your browser permits it, block clipboard access for the site and try again. If it does not, temporarily replace the awaited write with await Promise.reject(new Error('Practice failure')). Check the visible failure message, restore the real call and recheck success. This simulates rejection; it does not prove real permission behaviour.

ENOENT or a missing dependencyCheck the path and dependency name. For real calculator dependencies, run npm install from its root. Remove the deliberate fake entry first.
require is not definedDo not mix a CommonJS example into the .mjs report. Use import.
Clipboard rejectionUse localhost, trigger the action from a click, check site permissions and handle the rejection. Browser policies differ.
