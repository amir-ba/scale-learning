The calculator: from unpkg to npm + Vite

Lesson 0001 · Week 1 · part B (Build)

Time approx. 3 h Needs Node 24, your calculator repo (pushed, Scale from unpkg) Before part A (Study) of week 1 Cheat sheet package.json, npm, Yarn

Result: your calculator starts with npm run dev. It loads Scale from node_modules, not from unpkg. The change is merged with a pull request in your own repo.

1 · Three ideas (read first, 15 min)

Idea 1 — unpkg and npm deliver the same files

Your page loads a URL like this:

https://unpkg.com/@telekom/scale-components@next/dist/scale-components/scale-components.esm.js

This URL has three parts: the package name @telekom/scale-components, a version or tag next, and a path inside the package. unpkg is a CDN that serves files from the npm registry (unpkg.com). npm install downloads the same package into node_modules/, so the same file is then at:

node_modules/@telekom/scale-components/dist/scale-components/scale-components.esm.js

The Scale package.json has "unpkg": "dist/scale-components/scale-components.esm.js". This is the file unpkg serves if the URL has no path.

Idea 2 — package.json is the manifest of a project

It records the project name, the scripts, and the packages with their allowed versions. dependencies are needed when the code runs; devDependencies are needed only to develop and build (npm docs). The lock file records the exact installed versions, so every machine installs the same packages (npm docs).

C# comparison: package.json ≈ the PackageReference list in a .csproj; package-lock.json ≈ NuGet's packages.lock.json.

Idea 3 — the browser does not know node_modules

The browser needs a URL for every import. A bare specifier like '@telekom/scale-components/loader' is only a name, so the browser cannot load it alone (MDN: JavaScript modules). A tool such as Vite finds the name in node_modules for you. Vite also gives a fast dev server and a production build in dist/.

2 · Steps (approx. 2 h)

For each step: before you run a command, think: what do I expect? After it, look at what changed. If the result surprises you and you cannot explain it, put it on your question list. Type the commands; do not copy them.

These steps were tested on 2026-10-02 with Node 24.18, npm 11.16, Vite 8.3 and Scale 3.0.0-beta.161. They work in dev mode and in a build, with no Vite config file.

  1. Check the tools. Node must be 24.x (Scale needs 24). 
    node -v
npm -v
  2. Go to your calculator folder. Make sure all work is committed, then make a branch for this week. 
    git status
git switch -c npm-vite
  3. Make a package.json. Open it and read each field. Which ones do you understand already? 
    npm init -y
  4. Look at the tags on npm before you install. Compare latest and next. 
    npm view @telekom/scale-components dist-tags
    Check your answer (open after you ran the command)

    On 2026-10-02: latest: 3.0.0-beta.161 and next: 3.0.0-beta.156. So @next is older than @latest. But the Scale README tells users to install @next. This is a real documentation bug. Bring it to the sync — it can become your first, very small pull request to Scale.

  5. Install Scale as a runtime dependency and Vite as a dev dependency. 
    npm install @telekom/scale-components
npm install -D vite
    Now open package.json, package-lock.json and node_modules/@telekom/scale-components/package.json. In the last one, find the fields unpkg, module and types. Commit.
  6. Add three scripts to package.json: 
    "scripts": {
  "dev": "vite",
  "build": "vite build",
  "preview": "vite preview"
}
  7. Make a .gitignore file with these two lines. Then git status must not show node_modules/. 
    node_modules/
dist/
  8. Remove the unpkg <link> and <script> tags from index.html. Make sure your main script tag has type="module", e.g. <script type="module" src="./main.js"></script>.
  9. At the top of your main JS file, load Scale from the package. This is the official way from the Scale README: 
    import '@telekom/scale-components/dist/scale-components/scale-components.css';
import { defineCustomElements } from '@telekom/scale-components/loader';

defineCustomElements(window);
  10. Start the dev server and open the URL it shows (normally http://localhost:5173). 
    npm run dev
    The calculator must work as before. Open DevTools → Network and reload: the Scale files now come from localhost, not from unpkg. Commit.
  11. Make a production build and look into dist/. Why are there many *.entry-*.js files? (Hint: Stencil loads the code of each component only when the page uses it. This is "lazy loading".) 
    npm run build
npm run preview
  12. Push the branch and open a pull request in your own repo (GitHub: "Compare & pull request"; GitLab: "merge request"). Read your own diff in the PR like a reviewer. Then merge it. 
    git push -u origin npm-vite
    GitHub docs: Creating a pull request

If something goes wrong

You seeCause and fix
Empty page, or import errors in the consoleYou opened index.html with a double-click (file://). Use the URL from npm run dev.
Console: "… has already been defined"An old unpkg tag is still in index.html. Scale loads two times. Remove the tag.
git status shows thousands of filesnode_modules/ is not in .gitignore. Do step 7 again.
Lines that start with npm warnWarnings, not errors. Read them, but they do not stop the install.
Components show as plain text, no styleThe CSS import (step 9, first line) is missing or has a typo.

3 · Check yourself

Answer alone, without the sources. You get feedback at once.

Without Vite, a plain module script does import … from '@telekom/scale-components/loader'. What happens?

Why is Vite in devDependencies, but Scale in dependencies?

Which one must you commit to git?

In @telekom/scale-components@next, what is next?

Evidence of learning (for the learning record): the student can predict what step 10 shows in the Network tab, and can explain it without help. The commits are small and node_modules/ is not in the diff.

Questions? Put them on your question list and bring it to the sync. If a question blocks you for more than 30 minutes, send it to your mentor before the sync.
