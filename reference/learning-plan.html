Learning plan

From browser JavaScript to a first bug fix in Telekom Scale · approx. 8 weeks at 6–10 h/week

Reader mentor Learner first-year informatics student (C++, OOP, HTML/JS basics) Mission MISSION.md Sources RESOURCES.md

End goal: one pull request from a fork to telekom/scale (main) that fixes a small bug, has a test, uses a Conventional Commit message, and passes CI (Prettier, TSLint, spec + e2e tests).

How the plan works

  • One lesson ≈ one session (60–90 min with the mentor) plus 2–4 h self-study from the primary source.
  • Every phase ends with a milestone the student shows to the mentor. Do not move on before the milestone works.
  • Spacing: start each session with 3 short recall questions from older lessons (no notes). This builds long-term memory.
  • One running project: the student's calculator. It moves from unpkg → npm + Vite → TypeScript. Then the student moves to the Scale repo.
  • Pattern bridge: name the design pattern when it shows up (Observer = DOM events / Stencil @Event; Decorator = @Component, @Prop; Composite = slots; Proxy = the generated React/Vue wrappers).

Phases

Phase 1 · week 1

Node.js and npm: from unpkg to package.json

topics what Node.js is (a JS runtime outside the browser) · package.json fields · dependencies vs. devDependencies · npm scripts · semver (^, ~, pre-release) · dist-tags · lock files · ES modules vs. CommonJS · npx

read Node.js Learn: npm intro · npm: package.json · npm: semver · Node: Packages

watch Fireship: Node.js in 7 steps · Fireship: Vite in 100 s

lessons 0001 Calculator from unpkg to npm + Vite · 0002 Read a real package.json (Scale) and semver · 0003 Write a small Node script (read scale-icons.json, ESM vs. CJS)

The calculator runs with npm run dev, uses Scale from node_modules, and the student explains every line of its package.json.

Phase 2 · week 2

The toolchain and the Scale monorepo

topics bundler · dev server · transpiler · formatter (Prettier) · linter (TSLint in Scale) · Yarn 1 vs. npm · Yarn workspaces · Lerna · Node version (engines.node: 24.x) · Windows: use WSL2 or Git Bash (Scale scripts use bash)

read MDN: Understanding client-side tools · Vite: Why Vite · Yarn 1 workspaces · Lerna intro

lessons 0004 The toolchain map (what runs when you type yarn start) · 0005 Scale on your machine: fork, clone, yarn bootstrap, yarn start in packages/components

Scale dev server runs locally. The student explains each script in the root and the packages/components package.json.

Phase 3 · weeks 3–4

TypeScript for a C++ programmer

topics structural vs. nominal typing (main difference to C++) · type annotations · interface vs. type · union types and narrowing · optional ? · generics (vs. C++ templates) · classes, access modifiers · decorators · .d.ts files · tsconfig.json · types are erased at runtime

read TS for Java/C# programmers (start here) · TS Handbook · Decorators

practice Total TypeScript beginner tutorial · TS Playground

lessons 0006 From JSDoc to TypeScript (the calculator) · 0007 Unions, narrowing, generics · 0008 Decorators and tsconfig (read Scale's tsconfig.json)

The calculator is in TypeScript; npx tsc --noEmit passes with strict: true.

Phase 4 · weeks 4–5

Web Components in depth, then StencilJS

topics Shadow DOM · <slot> · :host · ::part() · CSS custom properties and design tokens (--telekom-*) · attributes vs. properties · custom events (Observer pattern) · Stencil: @Component, @Prop, @State, @Event, @Watch, @Element, @Method · JSX render() · <Host> · lifecycle · generated readme.md

read MDN: Using shadow DOM · MDN: CSS custom properties · Stencil: Component · Stencil: API · Stencil: Lifecycle

lessons 0009 Inspect scale-button in DevTools (shadow root, parts, tokens) · 0010 Attributes, properties, events · 0011 Anatomy of a Stencil component: read divider.tsx line by line · 0012 Change a component locally (card or badge) and see it in the dev server

The student explains every line of packages/components/src/components/divider/divider.tsx and adds a small local change that works in the browser.

Phase 5 · week 6

Vue and the Scale Storybook

topics Vue concepts (template, props, reactivity, events) with Vue 3 · then Vue 2 Options API (props, data, methods) because Scale Storybook uses Vue 2.6 · Storybook 6 MDX stories · the Scale<Name>.vue wrapper pattern

read Vue tutorial · Vue 2 components · Vue and Web Components

watch Fireship: Vue in 100 s · Vue School: Vue 3 Fundamentals

lessons 0013 Vue in one hour (Vue 3 tutorial steps) · 0014 Read and change a Scale story (storybook-vue/stories/components/divider)

Storybook runs locally (components built first) and the student changes one story.

Phase 6 · weeks 6–7

Tests: Jest, snapshots, Stencil spec and e2e

topics describe/it/expect · snapshot tests and -u · Stencil newSpecPage · e2e with Puppeteer (newE2EPage) · run one test file · red → green (write a failing test that shows the bug, then fix)

read Jest: Getting started · Jest: Snapshots · Stencil: Unit testing · Stencil: E2E testing

lessons 0015 Read and run divider.spec.ts · 0016 Write a failing spec test first

The student writes a new spec test, sees it fail, makes it pass, and updates a snapshot on purpose.

Phase 7 · weeks 7–8

The first bug fix

topics fork + upstream remote · branch from main · claim the issue with a comment · reproduce in Storybook · small commits · Conventional Commits (fix(component): …) · rebase + force-push after review · @-mention a CODEOWNER · read CI output

read Scale CONTRIBUTING · GitHub: Contributing to a project · Conventional Commits · Learn Git Branching (rebase levels)

study small merged fixes: #2271 (1 line JSX) · #2396 (2 lines CSS) · #2447 (@Prop + @Watch)

lessons 0017 Git for contributors: fork, upstream, rebase, Conventional Commits · 0018 From issue to PR

A PR is open, CI is green, a maintainer is @-mentioned.
